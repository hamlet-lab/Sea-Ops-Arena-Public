# 공개 릴리스 체크리스트

중요한 변경을 병합하거나 외부에 공개하기 전에 아래 항목을 확인합니다.

## 저장소 출처

- [ ] 변경 내용은 이 공개 저장소 안에서 작성되었다.
- [ ] 비공개 커밋, 브랜치, 태그, 트리, 패치, blob을 가져오지 않았다.
- [ ] 비공개 저장소 이력을 merge, rebase, cherry-pick, force-push 방식으로 연결하지 않았다.

## 공개 범위

- [ ] 공개 내용은 Arena의 입력, 최종 결과, 합성 시나리오, 합성 환경 동작 또는 평가에 한정된다.
- [ ] 비공개 핵심 구현은 공개 인터페이스 뒤쪽에 남아 있다.
- [ ] 공개 타입·스키마가 비공개 내부 상태 구조를 그대로 모사하지 않는다.
- [ ] 비공개 정책·권한·판단·변경 반영 로직이 포함되어 있지 않다.
- [ ] 비공개 아키텍처, 연구, 특허, 발명 자료가 포함되어 있지 않다.
- [ ] 테스트, 예제, 오류 메시지, 다이어그램, 주석으로 내부 불변조건이나 설계가 역으로 드러나지 않는다.

## 정답 비노출 입력팩 v2

실제 모델·사람·외부 시스템의 판단을 생성했다면 다음을 확인합니다.

- [ ] 평가용 시나리오 JSON 자체를 판단 생성 대상에 제공하지 않았다.
- [ ] 공식 frozen 입력팩 `examples/input_packs/public_suite_v2.input.json`을 사용했다.
- [ ] 공식 입력팩 SHA-256이 `e68cf82311d4c4b6477799cf61aeb28b4f446d997e5a3c82b3c6ebb9680b88db`와 일치한다.
- [ ] `public_suite_v2.input.sha256` 검증이 통과한다.
- [ ] 같은 시나리오에서 생성기로 다시 만든 파일과 공식 frozen 입력팩이 바이트 단위로 일치한다.
- [ ] 입력팩에 `expected_decision`이 없다.
- [ ] 입력팩에 평가 태그, 평가 메모, 실행 기대 결과가 없다.
- [ ] 입력팩에 임의 metadata 또는 외부 context 참조가 없다.
- [ ] 입력팩의 공개 과제 ID가 표준 값과 일치한다.
- [ ] `proceed` / `reject` / `defer`의 공개 의미가 표준 계약과 일치한다.
- [ ] 입력팩에 `use_only_input_pack_content`, `no_external_tools_or_retrieval`, `return_final_status_map_only` 제약이 그대로 들어 있다.
- [ ] 필요한 request ID 목록과 cases의 request ID가 정확히 일치한다.
- [ ] 모델·사람·외부 시스템에는 해당 입력팩만 제공했다.
- [ ] frozen 입력팩을 수정해야 한다면 기존 파일을 덮어쓰지 않고 새 버전으로 만들었다.

## 실제 외부 baseline

- [ ] [`BASELINE_PROTOCOL.md`](BASELINE_PROTOCOL.md)의 text-only / no-tools 조건을 사용했다.
- [ ] 반복마다 이전 대화 상태를 재사용하지 않았다.
- [ ] 같은 모델·버전·입력팩으로 최소 3회 반복했다.

## 결과 유효성 검토

예상 밖 결과 또는 실행 이상이 있었다면 공개 결과로 확정하기 전에 다음을 확인합니다.

- [ ] 기대값과 다른 결과를 곧바로 모델·시스템 실패로 확정하지 않았다.
- [ ] 올바른 frozen 입력팩이 실제로 사용되었는지 확인했다.
- [ ] 실행 조건이 baseline 프로토콜과 일치했는지 확인했다.
- [ ] 출력 파싱·결과 변환·ID 매핑 오류가 없는지 확인했다.
- [ ] 시나리오 문장이 모호하거나 정보가 부족하지 않은지 확인했다.
- [ ] 공개 기대값 또는 평가 기준 자체에 결함이 없는지 검토했다.
- [ ] 입력·실행·파싱·환경 문제라면 해당 run을 무효 실행으로 분류하고 baseline 집계에서 제외했다.
- [ ] 벤치마크 결함이라면 기존 결과를 억지로 채점하지 않고 새 버전으로 수정한 뒤 다시 평가했다.
- [ ] 충분히 판단할 수 없는 경우 미해결 상태로 두고 공개 canonical result로 확정하지 않았다.
- [ ] 유효성 검토를 통과한 run 중 유리한 결과만 임의로 선택하지 않았다.

검토 과정의 원본 로그, 시행착오, 내부 논의 전체를 공개 저장소에 전시할 필요는 없습니다. 공개 대상은 **유효성 검토가 끝난 최종 결과와 그 결과를 재현하는 데 필요한 조건**입니다.

## 실제 외부 결과 파일

- [ ] 공개하는 결과는 유효성 검토를 통과했다.
- [ ] 원본 로그를 복사해 지우는 방식이 아니라 공개 결과 템플릿을 기준으로 작성했다.
- [ ] `public-decision-set-v1` 허용 필드만 사용했다.
- [ ] `suite_sha256`이 정확한 평가용 시나리오 파일과 일치한다.
- [ ] `input_pack_sha256`이 실제 판단 생성에 사용한 입력팩 전체와 일치한다.
- [ ] 평가 시 `--input-pack`을 함께 제공해 결합 검증을 통과했다.
- [ ] 모든 request ID가 정확히 대응되며 누락·불필요 ID가 없다.
- [ ] 반복 결과라면 `repeat_id`가 고유하며 같은 출처·모델 버전·입력팩끼리만 묶었다.
- [ ] 원본 비공개 프롬프트, 시스템 메시지, 응답 전문, 내부 추론·작업 로그를 결과 파일에 넣지 않았다.
- [ ] 실제 외부 결과를 저장소에 공개한다면 참조 입력팩 파일도 함께 공개했다.

## 민감정보

- [ ] `sea-ops-arena-audit --root .` 결과가 깨끗하다.
- [ ] 비밀정보·자격증명 검사 결과가 깨끗하다.
- [ ] 내부 명칭 검사 결과가 깨끗하다. 검사 차단 목록은 이 저장소 밖에서 관리한다.
- [ ] 실제 운영 엔드포인트, 고객 데이터, 비공개 로그, 프롬프트 원본, 인프라 비밀정보가 없다.

## 의미 단위 검토

- [ ] 여러 공개 파일을 조합했을 때 비공개 내부 구조를 추론할 수 있는지 검토했다.
- [ ] 공개 스키마는 벤치마크 목적에 맞게 독립적으로 설계되었으며 비공개 스키마를 복사하지 않았다.
- [ ] 공개 예제는 합성 데이터이며 내부 업무 흐름을 재구성하지 않는다.
- [ ] 공개 지표가 비공개 내부 평가 기준을 그대로 재현하지 않는다.
- [ ] 입력팩과 공개 결과를 함께 보아도 비공개 판단 과정이 드러나지 않는다.
- [ ] 커밋 메시지에 비공개 구현 세부사항이 없다.

## 최종 확인

- [ ] 전체 diff를 확인했다.
- [ ] 새로 추가되거나 삭제된 파일을 확인했다.
- [ ] pytest가 통과했다.
- [ ] 공개 릴리스 감사가 통과했다.
- [ ] 정답 비노출 입력팩 CLI가 통과했다.
- [ ] 공식 frozen 입력팩 재생성 비교가 통과했다.
- [ ] 공식 frozen 입력팩 SHA-256 검증이 통과했다.
- [ ] 결과 유효성 검토가 완료되었다.
- [ ] 단일 평가 CLI가 통과했다.
- [ ] 비교 CLI가 통과했다.
- [ ] 반복 평가 CLI가 통과했다.
- [ ] 공개 결과 템플릿 CLI가 통과했다.
- [ ] 문서를 확인했다.
- [ ] 자동 생성 결과물을 확인했다.

한 항목이라도 판단이 애매하면 해당 세부사항은 공개하지 않습니다.
