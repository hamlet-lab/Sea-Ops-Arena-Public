# 공개 시나리오 작성 원칙

SEA Ops Arena의 공개 시나리오는 **외부에서 재현할 수 있는 평가 문제**를 만들기 위한 합성 데이터입니다.

이 문서에 적힌 사례와 기대값은 비공개 의사결정 시스템의 규칙, 정책표, 내부 상태 또는 구현 방식을 옮긴 것이 아닙니다.

## 현재 공개 세트

`examples/scenarios/public_suite_v2.json`에는 4개 영역의 합성 사례 12개가 포함되어 있습니다.

| 영역 | 사례 수 | 공개 예시의 범위 |
|---|---:|---|
| 고객지원 | 3 | 정상 요청, 입력 충돌, 정보 누락 |
| 사무 운영 | 3 | 정상 구매, 정보 누락, 중복 요청 |
| 재고 관리 | 3 | 정상 보충, 중복 작업, 수량 충돌 |
| 시설 운영 | 3 | 정기 점검, 대상 불일치, 경보 점검 |

각 영역은 특정 산업 시스템의 실제 정책을 재현하지 않습니다. 입력과 기대값을 사람이 읽고 이해할 수 있도록 단순화한 공개 합성 문제입니다.

## 기대 판단의 의미

공개 사례에는 `proceed`, `reject`, `defer` 중 하나의 기대값이 들어 있습니다.

- `proceed`: 이 공개 문제에서는 실행 진행을 기대하는 사례
- `reject`: 이 공개 문제에서는 실행하지 않기를 기대하는 사례
- `defer`: 이 공개 문제에서는 추가 확인 뒤 판단하기를 기대하는 사례

이 세 값은 **Arena에서 결과를 비교하기 위한 공개 라벨**입니다. 어떤 비공개 시스템이 내부에서 사용하는 상태, 단계, 정책 분류 또는 권한 구조를 뜻하지 않습니다.

## 시나리오를 추가할 때의 기준

새 공개 사례는 다음 조건을 만족해야 합니다.

1. 합성 데이터이거나 공개 배포가 허용된 데이터일 것
2. 사람이 입력과 기대값을 독립적으로 이해할 수 있을 것
3. 특정 비공개 구현의 내부 규칙을 알아야만 정답을 이해할 수 있는 문제가 아닐 것
4. 내부 코드명, 정책명, 상태명, 시스템 경로, 실제 운영 식별자를 포함하지 않을 것
5. 여러 사례를 조합해도 비공개 아키텍처를 역추론하는 단서가 되지 않을 것
6. 실제 모델 또는 실제 SEA 결과가 아니라면 반드시 합성/예시임을 표시할 것

## 공개 세트의 목적

이 시나리오의 목적은 특정 시스템의 내부 판단 원리를 설명하는 것이 아니라, **서로 다른 판단 결과를 동일한 조건에서 실행하고 관찰할 수 있는 공통 시험장**을 제공하는 것입니다.

따라서 앞으로 실제 모델이나 외부 시스템의 결과를 연결하더라도 시나리오 형식과 공개 지표는 유지할 수 있으며, 연결된 시스템의 내부 구현은 공개할 필요가 없습니다.
