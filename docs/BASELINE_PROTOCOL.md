# 실제 모델 Baseline 프로토콜

이 문서는 SEA Ops Arena에 **첫 실제 외부 모델 결과**를 추가할 때 사용하는 공개 평가 절차입니다.

목적은 특정 모델을 유리하게 만드는 것이 아니라, 같은 입력 조건에서 결과를 다시 비교할 수 있도록 실험 조건과 결과 유효성 기준을 고정하는 것입니다.

## 공식 baseline 입력팩

첫 baseline부터 다음 파일을 **고정 입력**으로 사용합니다.

- 평가용 시나리오: `examples/scenarios/public_suite_v2.json`
- 모델용 입력팩: `examples/input_packs/public_suite_v2.input.json`
- 입력팩 SHA-256: `e68cf82311d4c4b6477799cf61aeb28b4f446d997e5a3c82b3c6ebb9680b88db`

입력팩은 `arena-input-pack-v2` 생성기로 만들어진 결과를 저장소에 그대로 고정한 파일입니다. CI는 같은 시나리오에서 입력팩을 다시 생성한 뒤 공식 파일과 **바이트 단위로 비교**하고, 별도 `.sha256` 파일도 검증합니다.

따라서 첫 baseline 결과가 위 해시와 다른 입력팩을 가리키면 같은 실험으로 취급하지 않습니다.

## 기본 트랙: text-only / no-tools

첫 baseline은 다음 조건을 사용합니다.

1. 공식 frozen 입력팩을 그대로 사용합니다.
2. 모델에는 해당 입력팩의 내용만 제공합니다.
3. 입력팩 밖의 웹검색, RAG, 외부 도구, 별도 문서를 사용하지 않습니다.
4. 모델에는 다른 반복 실행의 답이나 평가 정답을 제공하지 않습니다.
5. 각 반복은 이전 반복의 대화 상태를 재사용하지 않는 새 실행으로 수행합니다.
6. 공개 결과에는 설명이나 추론 과정을 저장하지 않고 request ID별 최종 상태만 남깁니다.
7. 동일 모델·동일 버전·동일 입력팩으로 최소 3회 반복합니다.
8. 기대값과 다른 결과나 실행 이상은 즉시 실패로 확정하지 않고 먼저 유효성을 검토합니다.

입력팩 v2 자체에도 다음 실행 제약이 포함되어 해시에 함께 고정됩니다.

- `use_only_input_pack_content`
- `no_external_tools_or_retrieval`
- `return_final_status_map_only`

## 모델에 전달하는 정보

모델에 전달하는 내용은 `examples/input_packs/public_suite_v2.input.json`의 내용입니다.

입력팩 안에는 다음이 포함됩니다.

- 공개 과제 설명
- `proceed` / `reject` / `defer`의 공개 의미
- 출력 계약
- 12개 합성 사례의 공개 정보

다음은 포함되지 않습니다.

- 평가 기대값
- 평가 태그
- 평가 메모
- SEA 내부 구조 또는 판단 정보
- 비공개 프롬프트나 시스템 메시지
- 이전 반복의 답

## 입력팩 무결성 확인

실험을 시작하기 전 고정 파일의 해시를 확인할 수 있습니다.

```bash
cd examples/input_packs
sha256sum -c public_suite_v2.input.sha256
```

또는 생성기로 다시 만든 결과와 비교할 수 있습니다.

```bash
sea-ops-arena-input-pack \
  --suite examples/scenarios/public_suite_v2.json \
  --output /tmp/public_suite_v2.input.json

cmp /tmp/public_suite_v2.input.json examples/input_packs/public_suite_v2.input.json
```

## 샘플링 설정

모델 또는 공급자가 명시적인 샘플링 설정을 지원한다면 첫 baseline에서는 가능한 한 낮은 무작위성 설정을 사용합니다.

다만 공급자마다 지원하는 설정이 다르므로 **지원하지 않는 매개변수를 억지로 에뮬레이션하지 않습니다.** 모델명·버전과 반복 결과를 함께 공개하고, 동일 모델의 변동은 Arena의 반복 판단 안정률로 확인합니다.

## 반복 횟수

첫 공개 baseline의 최소 반복 횟수는 **3회**입니다.

3회는 최종 성능 통계로 충분하다는 의미가 아니라, 다음을 처음 확인하기 위한 최소 단위입니다.

- 같은 입력에서 판단이 반복 가능한지
- 특정 사례만 불안정하게 바뀌는지
- 평균 판단 일치율과 반복 안정성이 서로 다른지

정식 비교 자료로 확장할 때는 반복 횟수를 늘릴 수 있습니다.

## 결과 유효성 검토

Arena의 기대값과 실제 결과가 다르다는 사실만으로 곧바로 모델 또는 연결 시스템의 실패로 확정하지 않습니다. **불일치는 먼저 검토가 필요한 신호**로 취급합니다.

공개 결과로 확정하기 전에 최소한 다음을 확인합니다.

- 올바른 frozen 입력팩이 실제로 사용되었는가
- 실행 조건이 baseline 프로토콜과 일치했는가
- 출력 파싱이나 결과 변환 과정에 오류가 없었는가
- 시나리오의 정보가 충분하고 문장이 모호하지 않은가
- 공개 기대값 또는 평가 기준 자체에 결함이 없는가

검토 결과는 다음 중 하나로 정리합니다.

- **유효 결과**: 입력·실행·평가 조건이 정상이며 결과를 평가에 사용할 수 있음
- **무효 실행**: 입력 전달, 실행 조건, 파싱 또는 환경 문제로 같은 실험으로 인정할 수 없음
- **벤치마크 수정 필요**: 시나리오·기대값·평가 기준에 실제 결함이 확인됨
- **미해결**: 어느 쪽인지 충분히 확인되지 않아 공개 결과로 확정하지 않음

무효 실행은 공개 baseline 집계에 포함하지 않습니다. 벤치마크 결함이 확인되면 기존 결과를 억지로 채점하지 않고 시나리오 버전을 갱신한 뒤 새 버전에서 다시 평가합니다.

반대로 **유효성 검토를 통과한 결과만 놓고 유리한 실행만 임의로 고르는 방식은 사용하지 않습니다.** 같은 조건의 유효 실행은 정해진 반복 단위로 함께 평가합니다.

이 검토의 목적은 결과를 좋게 만드는 것이 아니라 **무엇이 실제 시스템의 결과이고 무엇이 테스트 자체의 문제인지 분리하는 것**입니다. 원본 로그, 시행착오, 내부 검토 대화 전체를 공개할 필요는 없으며, 공개 저장소에는 검토를 통과한 최종 결과와 그 결과를 재현하는 데 필요한 조건만 남깁니다.

## 결과 파일

유효성 검토를 통과한 각 반복은 별도 `public-decision-set-v1` 파일로 저장합니다.

파일에는 최소한 다음 공개 정보가 들어갑니다.

- 결과 묶음 label
- 모델명
- 모델 버전
- 반복 ID
- `suite_sha256`
- `input_pack_sha256`
- request ID별 최종 상태

원본 모델 응답 전문이나 reasoning은 공개 결과 파일에 저장하지 않습니다.

## 평가 순서

각 유효 반복을 개별 평가한 뒤 동일 모델 결과를 반복 평가합니다.

```bash
sea-ops-arena \
  --suite examples/scenarios/public_suite_v2.json \
  --input-pack examples/input_packs/public_suite_v2.input.json \
  --decisions run-001.public.json
```

```bash
sea-ops-arena-repeat \
  --suite examples/scenarios/public_suite_v2.json \
  --input-pack examples/input_packs/public_suite_v2.input.json \
  --results run-001.public.json run-002.public.json run-003.public.json
```

여러 모델을 비교할 경우에도 **같은 평가용 시나리오와 같은 frozen 입력팩**을 사용합니다.

## 공개 전 검증

실제 결과를 저장소에 추가하기 전에 다음을 모두 통과해야 합니다.

1. 공식 frozen 입력팩 SHA-256 검증
2. 공식 입력팩과 생성기 재생성 결과의 바이트 단위 일치
3. 결과 파일 포맷 검증
4. request ID 커버리지 검증
5. `suite_sha256` 검증
6. `input_pack_sha256` 검증
7. 결과 유효성 검토
8. 공개 릴리스 감사
9. 저장소 밖 내부 명칭 검사
10. 여러 공개 파일을 조합한 의미 단위 역추론 검토

## SEA와의 경계

이 baseline 프로토콜은 **외부 모델 자체의 공개 baseline을 측정하기 위한 절차**입니다.

SEA가 연결된 실험을 추가하더라도 공개 저장소에는 동일하게 외부에서 관찰 가능한 입력과 최종 결과만 들어갑니다. SEA 내부 상태, 정책, 검증 과정, 실행 제어 구조를 baseline 프로토콜이나 결과 파일에 기록하지 않습니다.
