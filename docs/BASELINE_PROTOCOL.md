# 실제 모델 Baseline 프로토콜

이 문서는 SEA Ops Arena에 **첫 실제 외부 모델 결과**를 추가할 때 사용하는 공개 실험 절차입니다.

목적은 특정 모델을 유리하게 만드는 것이 아니라, 같은 입력 조건에서 결과를 다시 비교할 수 있도록 실험 조건을 고정하는 것입니다.

## 기본 트랙: text-only / no-tools

첫 baseline은 다음 조건을 사용합니다.

1. 평가용 시나리오 파일에서 `arena-input-pack-v2`를 생성합니다.
2. 모델에는 생성된 입력팩만 제공합니다.
3. 입력팩 밖의 웹검색, RAG, 외부 도구, 별도 문서를 사용하지 않습니다.
4. 모델에는 다른 반복 실행의 답이나 평가 정답을 제공하지 않습니다.
5. 각 반복은 이전 반복의 대화 상태를 재사용하지 않는 새 실행으로 수행합니다.
6. 공개 결과에는 설명이나 추론 과정을 저장하지 않고 request ID별 최종 상태만 남깁니다.
7. 동일 모델·동일 버전·동일 입력팩으로 최소 3회 반복합니다.
8. 실패하거나 기대값과 다른 결과도 제거하지 않습니다.

입력팩 v2 자체에도 다음 실행 제약이 포함되어 해시에 함께 고정됩니다.

- `use_only_input_pack_content`
- `no_external_tools_or_retrieval`
- `return_final_status_map_only`

## 모델에 전달하는 정보

모델에 전달하는 내용은 생성된 `arena-input-pack-v2` 파일의 내용입니다.

입력팩 안에는 다음이 포함됩니다.

- 공개 과제 설명
- `proceed` / `reject` / `defer`의 공개 의미
- 출력 계약
- 12개 합성 사례의 공개 정보

다음은 포함되지 않습니다.

- 평가 기대값
- 평가 태그
- 평가 메모
- SEA 내부 구조 또는 판단 정보
- 비공개 프롬프트나 시스템 메시지
- 이전 반복의 답

## 샘플링 설정

모델 또는 공급자가 명시적인 샘플링 설정을 지원한다면 첫 baseline에서는 가능한 한 낮은 무작위성 설정을 사용합니다.

다만 공급자마다 지원하는 설정이 다르므로 **지원하지 않는 매개변수를 억지로 에뮬레이션하지 않습니다.** 모델명·버전과 반복 결과를 함께 공개하고, 동일 모델의 변동은 Arena의 반복 판단 안정률로 확인합니다.

## 반복 횟수

첫 공개 baseline의 최소 반복 횟수는 **3회**입니다.

3회는 최종 성능 통계로 충분하다는 의미가 아니라, 다음을 처음 확인하기 위한 최소 단위입니다.

- 같은 입력에서 판단이 반복 가능한지
- 특정 사례만 불안정하게 바뀌는지
- 평균 판단 일치율과 반복 안정성이 서로 다른지

정식 비교 자료로 확장할 때는 반복 횟수를 늘릴 수 있습니다.

## 결과 파일

각 반복은 별도 `public-decision-set-v1` 파일로 저장합니다.

파일에는 최소한 다음 공개 정보가 들어갑니다.

- 결과 묶음 label
- 모델명
- 모델 버전
- 반복 ID
- `suite_sha256`
- `input_pack_sha256`
- request ID별 최종 상태

원본 모델 응답 전문이나 reasoning은 공개 결과 파일에 저장하지 않습니다.

## 평가 순서

각 반복을 개별 평가한 뒤 동일 모델 결과를 반복 평가합니다.

```bash
sea-ops-arena \
  --suite examples/scenarios/public_suite_v2.json \
  --input-pack model-input.json \
  --decisions run-001.public.json
```

```bash
sea-ops-arena-repeat \
  --suite examples/scenarios/public_suite_v2.json \
  --input-pack model-input.json \
  --results run-001.public.json run-002.public.json run-003.public.json
```

여러 모델을 비교할 경우에도 **같은 평가용 시나리오와 같은 입력팩**을 사용합니다.

## 공개 전 검증

실제 결과를 저장소에 추가하기 전에 다음을 모두 통과해야 합니다.

1. 결과 파일 포맷 검증
2. request ID 커버리지 검증
3. `suite_sha256` 검증
4. `input_pack_sha256` 검증
5. 공개 릴리스 감사
6. 저장소 밖 내부 명칭 검사
7. 여러 공개 파일을 조합한 의미 단위 역추론 검토

## SEA와의 경계

이 baseline 프로토콜은 **외부 모델 자체의 공개 baseline을 측정하기 위한 절차**입니다.

SEA가 연결된 실험을 추가하더라도 공개 저장소에는 동일하게 외부에서 관찰 가능한 입력과 최종 결과만 들어갑니다. SEA 내부 상태, 정책, 검증 과정, 실행 제어 구조를 baseline 프로토콜이나 결과 파일에 기록하지 않습니다.
