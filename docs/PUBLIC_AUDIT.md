# 공개 릴리스 감사

`sea-ops-arena-audit`는 SEA Ops Arena 공개 저장소에서 발생할 수 있는 **일반적인 실수성 공개 위험**을 자동으로 찾는 보조 도구입니다.

```bash
sea-ops-arena-audit --root .
```

## 자동으로 확인하는 것

현재 감사 도구는 다음을 확인합니다.

- `.env` 계열 파일
- 키·인증서로 흔히 사용되는 파일 확장자
- 공개 저장소에서 사용하지 않는 `private`, `internal`, `traces` 디렉터리 경로
- `*.public.json` 파일이 엄격 공개 결과 포맷을 따르는지
- `arena-input-pack-v1` 파일이 허용 필드만 가지는지
- 실제 외부 공개 결과에 `suite_sha256`이 있는지
- 실제 외부 공개 결과에 `input_pack_sha256`이 있는지
- `suite_sha256`과 일치하는 공개 시나리오가 저장소에 존재하는지
- `input_pack_sha256`과 일치하는 정답 비노출 입력팩이 저장소에 존재하는지

문제가 발견되면 종료 코드 1로 실패하므로 CI에서도 사용할 수 있습니다.

## 실제 결과를 공개할 때의 의미

실제 `model`, `human`, `external-system` 결과를 저장소에 추가하려면 **결과 파일만 올려서는 안 됩니다.**

해당 결과가 참조하는 정답 비노출 입력팩도 함께 공개해야 감사가 통과합니다.

이를 통해 외부 검토자는 다음을 확인할 수 있습니다.

- 평가 기준으로 어떤 시나리오 파일을 썼는지
- 판단 생성 대상이 실제로 어떤 정답 비노출 입력팩을 봤는지
- 결과 파일이 그 두 파일과 해시로 결합되어 있는지

감사 도구는 입력팩 내부에 평가 전용 필드가 들어오지 않았는지도 포맷 검증을 통해 확인합니다.

## 의도적으로 하지 않는 것

이 도구에는 **비공개 내부 명칭 목록을 넣지 않습니다.**

내부 프로젝트명·구성요소명·파일명 등을 public 저장소의 deny-list로 만들면, 그 목록 자체가 비공개 정보를 모아 둔 문서가 될 수 있기 때문입니다.

따라서 내부 명칭과 비공개 구조에 대한 검사는 이 저장소 밖의 별도 검토 절차에서 수행합니다.

또한 이 도구는 다음을 완전히 판정할 수 없습니다.

- 여러 평범한 파일을 조합했을 때 비공개 구조를 역추론할 수 있는지
- 기술 설명이 특허·연구 공개 범위를 넘어서는지
- 합성 시나리오가 비공개 업무 흐름을 지나치게 닮았는지
- 문장·도표·테스트가 의도치 않게 내부 설계 원리를 설명하는지
- 공개 최종 결과만으로 비공개 판단 과정을 과도하게 추정할 수 있는지

이 항목들은 자동 문자열 검사보다 **의미 단위 공개 검토**가 필요합니다.

## 권장 릴리스 순서

1. 공개 저장소에서만 새 코드를 작성합니다.
2. 실제 판단 생성에는 정답 비노출 입력팩만 사용합니다.
3. `python -m pytest`를 실행합니다.
4. `sea-ops-arena-audit --root .`를 실행합니다.
5. 결과의 시나리오·입력팩 해시와 request ID를 검증합니다.
6. 저장소 밖의 내부 명칭 검사와 의미 단위 검토를 수행합니다.
7. 전체 diff, 예제, 테스트, 문서, 커밋 메시지를 최종 확인합니다.

자동 감사가 통과했다는 사실만으로 공개 안전성이 보장되는 것은 아닙니다. 자동 감사와 별도 의미 검토를 함께 사용하는 것을 기본 원칙으로 합니다.
