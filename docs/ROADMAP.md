# 공개 개발 로드맵

이 문서는 SEA Ops Arena **공개판 자체**의 개발 방향을 설명합니다. SEA 또는 다른 비공개 시스템의 내부 개발 로드맵을 포함하지 않습니다.

## 현재 — v0.4

공개 벤치마크의 비교·재현·반복 평가와 안전한 외부 결과 입력 경계를 구현했습니다.

- 공개 요청·최종 판단 결과 계약
- 외부 시스템 연결용 최소 인터페이스
- 합성 실행 환경
- JSON 시나리오 입력
- 4개 업무 영역, 12개 공개 합성 사례
- 판단 일치율 / 불필요 실행 / 필요한 실행 누락 / 실행 성공률 집계
- 여러 판단 결과 파일의 동일 조건 비교
- 동일 출처 결과의 반복 판단 안정성 집계
- Markdown / JSON 결과 보고서
- 입력 파일 SHA-256 기반 재현 실행 식별자
- `manifest.json` / `report.md` / `results.json` 실행 결과 묶음
- 판단 결과 파일의 누락·불필요 ID 사전 검증
- 허용 필드 기반 `public-decision-set-v1`
- 실제 외부 결과와 공개 시나리오 파일의 SHA-256 결합 검증
- 원본 로그를 복사하지 않고 사용할 수 있는 공개 결과 템플릿 생성기
- 주요 CLI 경로를 포함한 자동 테스트 CI
- 공개/비공개 경계 및 시나리오·결과 작성 원칙 문서화

현재 저장소에 포함된 예시는 구조와 재현성을 검증하기 위한 **합성 데이터와 고정 응답**입니다. 실제 모델 또는 SEA 성능 결과가 아닙니다.

## 다음 — 실제 공개 결과 축적

다음 단계의 목표는 새로운 내부 구현을 공개하는 것이 아니라, 확정된 공개 경계를 이용해 실제 외부 결과를 안전하게 축적하는 것입니다.

권장 흐름은 다음과 같습니다.

1. 모델 또는 외부 시스템 실행은 비공개 환경에서 수행합니다.
2. 공개할 시나리오 파일을 먼저 확정합니다.
3. `sea-ops-arena-template`로 허용 필드만 가진 결과 템플릿을 생성합니다.
4. 원본 로그를 복사하지 않고 공개 가능한 최종 판단만 채웁니다.
5. 시나리오 SHA-256 결합과 request ID 커버리지 검사를 통과시킵니다.
6. 단일 실행·여러 결과 비교·반복 안정성 평가를 동일한 Arena에서 수행합니다.

실제 결과 파일에는 모델명·버전·기록 시각·반복 식별자처럼 외부 검증에 필요한 최소 출처 정보만 사용합니다.

다음 항목은 기본적으로 공개 결과 파일에 저장하지 않습니다.

- 비공개 시스템 프롬프트
- 내부 시스템 메시지
- 내부 추론 또는 작업 로그
- 비공개 상태·정책·판단 자료
- API 키, 토큰, 내부 URL, 파일 경로
- 공개 검토를 거치지 않은 원본 로그나 임의 metadata

## 이후 — 시나리오 확장

현재 12개 합성 사례를 기반으로 공개 문제의 폭을 넓힙니다.

후보 범위:

- 시간 순서가 중요한 요청
- 연속된 여러 작업
- 실행 실패가 포함된 사례
- 여러 요청 사이의 공개 충돌
- 서로 다른 업무 영역을 잇는 합성 사례
- 동일 문제의 난이도 변형

추가 시나리오도 특정 비공개 정책이나 내부 구조를 복제하지 않고, 외부에서 기대값을 독립적으로 이해할 수 있는 공개 문제로 작성합니다.

## 이후 — 공개 결과 시각화

코드를 읽지 않는 사람도 결과를 이해할 수 있도록 정적 리포트와 간단한 시각화를 추가합니다.

우선순위는 화려한 대시보드보다 다음 항목입니다.

- 어떤 시나리오 버전을 사용했는지
- 어떤 공개 결과 파일을 평가했는지
- 반복마다 결과가 얼마나 달라졌는지
- 불필요 실행과 필요한 실행 누락이 어디서 발생했는지
- 결과를 동일 입력으로 다시 확인할 수 있는지

## 유지되는 원칙

기능이 늘어나더라도 다음 원칙은 유지합니다.

1. 공개 벤치마크는 독립적으로 재현 가능해야 합니다.
2. 실제 결과와 합성 예시를 명확히 구분합니다.
3. 실패 사례를 숨기지 않습니다.
4. 공개 지표의 계산 방법은 설명할 수 있어야 합니다.
5. 외부 시스템의 비공개 내부 구현을 공개 벤치마크에 복제하지 않습니다.
6. 비공개 저장소의 Git 이력이나 내부 자료를 공개 저장소로 가져오지 않습니다.
7. 여러 공개 파일을 조합했을 때 비공개 구조를 역추론할 수 있는 정보도 공개하지 않습니다.
8. 실제 외부 결과는 원본 로그를 깎아 공개하는 방식보다 허용 필드 템플릿에 필요한 값만 옮기는 방식을 우선합니다.
